# 劳动仲裁请求、金额计算与证据编排专项

本模块用于劳动者准备申请劳动仲裁、修改仲裁请求、整理金额底稿和证据目录，以及为开庭形成可核验的案件结构。目标是在不遗漏劳动者潜在权益的前提下，把每项请求写成“主体正确、事实成熟、金额可算、证据对应、程序可受理”的完整单元；既不能只写用户最先想到的一项，也不能机械堆砌相互冲突或没有事实入口的请求。

先根据实体争议读取相应专项：试用期解除读 [probation-dismissal.md](probation-dismissal.md)，工资奖金提成读 [wage-bonus-commission.md](wage-bonus-commission.md)，PIP与不能胜任读 [pip-incompetence-dismissal.md](pip-incompetence-dismissal.md)，协商解除读 [mutual-termination-negotiation.md](mutual-termination-negotiation.md)，公司单方解除读 [unlawful-termination-remedies.md](unlawful-termination-remedies.md)。通用证据质量和依赖链读 [evidence-claim-matrix.md](evidence-claim-matrix.md)。

## 一、先做受理门槛检查

### 1. 是否属于劳动争议

区分劳动关系争议、劳务或承揽关系争议、社会保险经办争议、劳动能力鉴定异议及其他不属于劳动仲裁受理范围的事项。同一事件可能同时包含劳动仲裁、行政处理和普通民事诉讼路径，不把所有问题都塞入一份劳动仲裁申请书。

劳动关系本身有争议时，先判断是否需要提出确认劳动关系请求，并检查其与工资、解除、工伤待遇等下游请求的依赖关系。

### 2. 申请人和被申请人是否正确

逐一核对：

- 劳动合同签约主体；
- 工资支付、社保缴纳、考勤管理和解除决定主体；
- 实际工作安排和管理主体；
- 单位统一社会信用代码、注册地址及可核验状态；
- 是否存在派遣、承包、挂靠、关联公司轮流签约、合并分立、注销或无照经营；
- 自然人、关联公司或第三人是否有明确法律依据列入案件。

不能因为某公司参与管理或付款就当然把所有关联主体列为共同被申请人；也不能只按工资转账名称忽略合同和实际用工。主体不明时先形成主体关系图和证据清单，必要时转律师复核。

### 3. 管辖是否正确

全国基线是劳动合同履行地或者用人单位所在地的劳动争议仲裁委员会管辖；双方分别申请时还要审查履行地优先等规则。实际办公地、远程工作地、合同约定地、注册地址和社保缴纳地不能互相替代。

提交前到拟申请仲裁委员会的官方渠道核验：辖区划分、收件窗口、线上平台、预约方式、所需份数、身份证明、主体信息查询材料和当地格式。不得仅凭地图搜索或非官方中介信息确认管辖。

### 4. 仲裁时效

一般仲裁时效为一年，从当事人知道或者应当知道权利被侵害之日起计算。分别检查每项请求的起算点、持续状态、劳动关系存续期间拖欠劳动报酬的特殊规则，以及劳动关系终止后的一年期限。

同时核对是否存在：

- 向对方主张权利；
- 向有关部门请求权利救济；
- 对方同意履行义务；
- 不可抗力或其他正当理由；
- 申请仲裁、撤回、不予受理或另案程序留下的记录。

将中断、中止或特殊起算写成待证明事实，保存投诉、催告、调解、邮件、回执和受理材料。不要仅凭“我一直在沟通”就认定时效必然中断，也不要把一个请求的中断自动扩张到全部独立请求。

## 二、建立请求总表

### 0. 先做权益穷尽扫描

在用户核心请求之外逐项检查：履行劳动合同或恢复岗位、欠付工资和工资差额、加班费、奖金提成和报销、未休年休假工资、未签书面合同二倍工资、经济补偿、违法解除赔偿、符合法定条件的代通知金、竞业补偿、离职证明及档案社保转移、社保公积金行政补救、因单位原因不能领取失业保险待遇的损失，以及本案事实触发的工伤、医疗期、三期等权利。

用户陈述已经提供事实基础的，列入请求总表和文书；可能成立但缺少个性事实的，列入“待确认追加请求”，写明成立条件、所缺事实、计算方式和是否属于仲裁受理范围，并询问是否主张。用户确认后，下一轮直接交付加入新增请求的完整申请书、请求清单和金额底稿。不得自行填写加班时数、工资金额、未休天数、失业状态或单位过错。

继续履行、赔偿金、经济补偿等可能相互排斥或不能重复获得的请求，要设计主位、备位或解释程序选择；社保补缴等行政事项应单列行政路径，不为追求数量写成明显不属于仲裁受理范围的现金请求。

每项请求单独编号，并记录：

| 字段 | 内容 |
| --- | --- |
| 请求名称 | 确认、继续履行、支付、出具证明或其他明确救济 |
| 法律性质 | 劳动报酬、经济补偿、赔偿金、程序性请求等 |
| 基础事实 | 请求成立必须先证明的事实 |
| 法律要件 | 实体条件和程序条件 |
| 期间 | 起止日期及起算依据 |
| 计算 | 公式、参数、数据来源和结果 |
| 已付或抵扣 | 对方已履行部分及证据 |
| 证据 | 对应证据编号和证明目的 |
| 当前状态 | 未成熟、待核算、可申请或需专项复核 |
| 主要抗辩 | 主体、时效、事实、规则、金额、清结或重复请求 |

申请书中的请求必须具体、可执行。金钱请求原则上写明项目、期间和暂计金额；不能核实企业控制数据时，先写现有可证明部分和计算方法，并结合当地受理要求决定是否暂计，不凭空编造总额。

## 三、处理请求之间的关系

### 1. 上游与下游

- 确认劳动关系是部分工资、工伤或解除请求的上游事实；
- 公司作出解除是违法解除赔偿金或继续履行的上游事实；
- 单位违法事实、劳动者解除意思和送达是被迫解除经济补偿的上游事实；
- 工资或提成规则、完成条件和工作量是差额金额的上游事实。

上游证据不足时，在总表中标出断点，先补证或调整表达，不用增加更多下游请求掩盖问题。

### 2. 主请求、备选法律评价和不能并得的请求

继续履行与违法解除赔偿金不机械并列为同时获得。经济补偿与违法解除赔偿金也需按真实解除路径处理，不能对同一解除事实简单重复计算。确需主位、备位或庭审中变更时，结合当地仲裁受理方式、程序阶段和裁审衔接规则设计，并把真实事实保持一致。

劳动者主张违法解除赔偿金，裁审认定解除合法但依法应支付经济补偿的，关注仲裁与诉讼衔接意见的处理规则；不能因此省略经济补偿的适用事实和计算。

### 3. 可以并行但应分别证明的请求

解除救济、欠付工资、奖金提成、未休年休假、加班费、竞业补偿、离职证明和待遇损失可能并行，但每项都有独立期间、公式和证据。避免用同一段事实概括所有请求，也避免把工资、补偿、赔偿金统称为“损失”。

## 四、金额计算底稿

每项金钱请求使用同一套底稿字段：

1. 请求项目；
2. 计算期间；
3. 公式；
4. 每个参数及单位；
5. 参数来源和证据编号；
6. 已支付或应扣除金额；
7. 计算结果和舍入方式；
8. 待企业提供的数据；
9. 地方标准及核验日期；
10. 与申请书金额是否一致。

### 常见计算的控制点

- **工资差额**：按月份、工资组成、应发、已发和差额逐项列明；
- **加班费**：先证明加班事实，再区分工作日、休息日、法定节假日、调休和工资基数；
- **奖金提成**：按项目或考核周期列规则、条件、完成数据、核算日和已付金额；
- **未休年休假工资**：按年度列连续工龄、应休、已休、折算、工资基数和请求期间；
- **经济补偿或赔偿金**：核对解除路径、工作年限承继、月工资组成、十二个月期间、三倍封顶和已付项目；
- **未签书面合同二倍工资**：核对未签期间、一个月宽限、补签时间、特殊人员和时效，不按整个劳动关系期间机械计算；
- **待遇损失**：必须说明单位行为、待遇条件、实际未获待遇、金额标准和因果关系。

金额不能确定时，输出“已确认金额、可公式化但待数据金额、尚未成熟金额”三层，不用一个看似精确的总数掩盖缺失参数。地方平均工资、最低工资、社保待遇等动态数据必须在提交前从官方来源复核。

## 五、事实时间线只保留有法律意义的节点

时间线至少包括：

- 入职、合同签署和主体变化；
- 岗位、工资规则和关键制度告知；
- 争议行为首次发生、持续或变化；
- 劳动者异议、催告、申辩和公司回复；
- 协商、解除、终止、送达和最后工作日；
- 工资、奖金、社保和离职手续节点；
- 调解投诉、申请仲裁和时效中断线索。

每个节点标注来源、证据编号和是否有冲突。不要把情绪评价、无法验证的动机判断和重复聊天全部堆进时间线；对不利事实不得隐瞒，应说明其影响和回应证据。

## 六、证据目录按争点编排

建议顺序：

1. 主体和劳动关系；
2. 劳动合同内容、岗位和工资规则；
3. 争议行为或工作完成事实；
4. 解除、辞职、协商或终止性质；
5. 金额和计算参数；
6. 沟通、异议、申辩和送达；
7. 时效、管辖和其他程序事实。

每项证据目录至少写：编号、名称、形成时间、来源或持有人、页码或载体、证明目的、原件状态和真实性补强。证明目的必须指向具体事实，例如“证明公司于某日以通知中所载理由解除”，而不是只写“证明案件事实”。

### 电子证据

保存原设备、原始文件、完整对话上下文、账号主体、发送接收时间、附件、导出文件及必要的录屏路径。截图用于快速呈现，但不能当然替代原始载体。对录音说明时间、地点、参与人和未剪辑原件；制作文字整理稿时标明其为辅助阅听材料。

### 企业控制证据

对考勤、工资台账、绩效后台、项目结算、规章制度制定公示等企业掌握材料，列明：劳动者已经完成的初步举证、材料由谁控制、为何与争点直接相关、请求对方提交或申请调查的具体范围。不得用“全部证据都在公司”代替自己的证据目录，也不得提出无限范围的调查申请。

### 提交与原件

按当地要求制作申请书和证据副本，保留完整自用庭审本。提交前核对页码、目录、附件、遮挡无关个人信息及副本一致性；原件原则上自行妥善保存并按通知携带核对，不把唯一原件无留痕交给非正式人员。

## 七、仲裁申请书生成规则

申请书至少包括：

- 申请人和被申请人准确身份信息；
- 仲裁请求，逐项编号；
- 事实与理由，围绕请求依赖链组织；
- 向有管辖权仲裁委员会提出申请；
- 日期和签名所需位置；
- 与当地表格相匹配的附件清单。

写作时遵循：

1. 请求部分写可裁判的结果，不在请求中混入长篇事实和情绪评价；
2. 事实理由部分先写劳动关系和主体，再按争点和时间说明；
3. 只引用能够核验的文件、对话、日期和金额；
4. 法律条文服务于要件，不大量堆砌；
5. 申请书、计算底稿、证据目录中的主体、期间、金额和编号必须一致；
6. 关键事实、主体、解除性质或金额缺失时，使用占位符并标为复核稿，不称可直接提交定稿。

## 八、提交前24小时检查

### 今天必须保存

- 即将超过时效的请求及中断线索；
- 主体登记、合同、解除或辞职通知、工资流水和送达原件；
- 企业账号中可能因离职失效的合法个人争议材料；
- 申请书、请求总表、计算底稿、证据目录的最终一致版本；
- 线上提交回执、窗口收件清单、补正通知和联系电话。

### 提交前必须问清

1. 具体由哪个仲裁委员会受理，依据履行地还是单位所在地；
2. 每项请求的起算日、截止日和时效证据；
3. 是否漏列必要主体或错误加入无依据主体；
4. 每项金额能否从底稿复算，是否有待企业数据；
5. 请求之间是否重复、冲突或依赖尚未成熟；
6. 申请书、证据目录、页码和附件数量是否一致；
7. 当地要求纸质、线上或两者并行，是否需要预约和补充表格。

### 是否发文

仲裁前是否再向公司发函取决于时效、证据和风险：

- 金额或项目状态不明且时效充足，可先发核算确认；
- 解除状态不明，可先发状态和履职确认；
- 时效临近、企业注销或资产恶化时，不因等待回复耽误申请；
- 被迫解除等不可逆文书仍按专项停止规则处理，不能为了“仲裁材料好看”补发与真实历史不符的通知。

## 九、立案后与开庭前

- 保存受理通知、案号、举证通知、开庭通知和送达时间；
- 按期限提交补充证据、变更请求、证人或调查申请；
- 新增请求时判断与原争议是否同一依赖链，避免进入诉讼后才发现独立请求未经仲裁前置；
- 收到答辩和企业证据后，制作“承认、否认、不知情、真实性异议、证明目的异议、反证”表；
- 用请求为单位形成开庭提纲：要件、证据、对方抗辩、回答和金额；
- 调解时逐项核对本金、付款日、税费、清结范围、违约、证明和执行，不只看总金额；
- 仲裁庭逾期、终局裁决、起诉或撤销程序分别核验法定条件和期限，不凭经验口号处理。

## 十、停止规则

出现以下情况优先转律师复核：

- 时效可能在数日内届满，或者中断、中止存在重大争议；
- 主体注销、破产、合并分立、关联公司或派遣承包关系复杂；
- 工伤职业病、三期、死亡待遇、群体争议或人身安全；
- 高额奖金提成、股权期权、竞业、商业秘密或刑事指控；
- 请求继续履行但岗位、主体或实际履行条件发生重大变化；
- 已签清结协议，拟主张撤销、无效或恢复原始请求；
- 已经收到不予受理、裁决书、撤销申请或法院文书，程序期限正在运行。

## 十一、专项输出顺序

1. 受理范围、主体、管辖和时效结论；
2. 用户目标及当前最重要的一至三项请求；
3. 请求总表、依赖链和成熟度；
4. 金额计算底稿及待核参数；
5. 事实时间线和冲突事实；
6. 证据目录、质量、缺口和补强；
7. 企业抗辩及回应结构；
8. 仲裁申请书或补正稿；
9. 提交清单、送达回执和程序期限；
10. 开庭准备、调解条款及律师复核事项。
