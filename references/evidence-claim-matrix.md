# 争点、证据与请求依赖矩阵

本文件用于把劳动者的叙述转换为可核验的事实、证据任务和行动选择。它不是裁判结果预测，也不能替代对现行法律、地方口径和具体材料的核验。

## 一、先检查基础事实，再处理派生请求

每项请求先画出依赖链。上游事实尚未达到初步证明门槛时，不把下游请求写成确定结论。

常见依赖链：

- 工资或提成请求：劳动关系与期间 -> 工资或提成规则 -> 完成条件或工作量 -> 应付金额 -> 已付金额 -> 差额。
- 被迫解除经济补偿：单位具体违法行为 -> 行为达到法定程度 -> 劳动者以该事由作出解除 -> 通知有效送达 -> 补偿基数和年限。
- 违法解除救济：单位作出解除 -> 解除理由和时间固定 -> 实体要件 -> 程序要件 -> 继续履行条件或赔偿金计算。
- 未休年休假工资：连续工作年限 -> 当年度应休天数 -> 已休或折抵情况 -> 单位安排和记录 -> 工资基数 -> 年度及期限。
- 未订立无固定期限劳动合同责任：合同次数和期限 -> 是否达到订立条件 -> 劳动者真实意思表示 -> 后续合同签署和异议 -> 责任期间。
- 失业保险待遇损失：应参保主体 -> 实际参保和缴费 -> 中断就业原因 -> 申领条件 -> 未获待遇与单位行为之间的因果关系 -> 当地标准。

如果同一上游事实支撑多个请求，应提示“一处举证失败可能同时影响多项请求”。

## 二、证据质量和状态

### 证据状态

对每项关键事实标注：

- 已取得：当前可以提交或出示；
- 缺失：没有直接材料；
- 相互冲突：不同材料、时间或陈述不一致；
- 待核实：已有线索，但来源、完整性或真实性尚未确认。

### 证据质量等级

证据强弱不能仅按文件名称判断。结合来源、原始载体、上下文、形成时间、取得方式和其他印证，暂按下列层级管理：

1. 原始载体、后台记录、正式文件或可核验电子数据；
2. 对方明确确认，或多个独立来源相互印证的材料；
3. 来源可以说明的复印件、截图或转发件，并有旁证支持；
4. 单方制作的统计表、整理表、回忆记录或孤立截图；
5. 只有口头陈述，尚无可验证线索。

层级是取证优先级，不是预判法院是否采信。对电子材料同时检查账号主体、完整上下文、原始设备或导出文件、时间、附件和连续性。

### 举证责任表达

不得简单回答“单位负举证责任，所以劳动者不用取证”。应分别说明：

- 劳动者需要完成的初步举证；
- 依法或通常由单位掌握管理的记录；
- 可以要求单位说明、提交或在程序中申请调取的材料；
- 单位不提交可能产生的不利后果；
- 在仲裁庭作出举证责任分配前，劳动者仍应采取的合法补证措施。

## 三、通用处理矩阵

### 1. 工资、降薪、奖金和提成

**要证明的核心事实**

- 工资构成是固定工资、绩效、提成、补贴还是混合结构；
- 计算规则、触发条件、核算周期、审批人和支付时间；
- 劳动者完成的工作、项目阶段、回款或验收状态；
- 单位已经支付的项目和双方差额；
- 是否存在现金支付、第三方支付或个人账户支付。

**优先保存**

- 合同、录用通知、薪酬制度及其历史版本；
- 工资条、银行流水、个税申报、社保基数和工资确认记录；
- 项目清单、工作量、验收、回款、结算、审批和历史发放样本；
- 单位对规则、金额、扣款或暂缓发放的回复。

**下一次沟通**

- 请单位分项说明本期应发、扣减、已发和未发金额；
- 请确认适用的计算规则、版本、完成条件和数据来源；
- 提成未结算时，请确认每个项目尚缺的条件、预计核算节点和负责部门；
- 现金工资主张缺少凭证时，优先询问固定金额、发放人、日期、地点和既往确认方式，不诱导对方作虚假承认。

**是否发文**

金额、规则或支付状态存在实质争议时，通常先发送工资或提成核算确认函；尚不能列出差额构成时，不直接发送带确定总额的催款定稿。

**请求成熟门槛**

至少能够说明计算规则或稳定支付惯例、对应工作事实和已付差额。只有劳动者单方制作的汇总表时，先补来源与印证。

### 2. 调岗、降薪、停派任务和PIP

**要证明的核心事实**

- 原岗位、职责、薪酬和工作地点；
- 单位作出的具体变化及开始时间；
- 合同、制度或双方协商中是否存在调整依据；
- 调整的业务理由、针对性、幅度和实际后果；
- 劳动者是否提出异议并继续正常履职。

**优先保存**

- 调整前后的岗位、任务、权限、排班、绩效和收入对比；
- 停派任务、移出群聊、关闭账号或拒绝进入的完整记录；
- 劳动者到岗、请示任务、提交成果和表达异议的记录。

**下一次沟通**

- 请明确是临时安排、协商变更、考核措施还是已经作出的正式决定；
- 请说明依据、期限、考核标准、薪酬影响和下一工作日安排；
- 询问任务减少是业务变化还是针对个人，以及后续如何分配。

**是否发文**

口头调整或事实停工时，优先发送履职及工作安排确认；已收到正式决定时，再根据用户目标发送异议或协商回复。不得默认建议拒绝工作或不到岗。

### 3. 被迫解除和经济补偿

**要证明的核心事实**

- 单位违法行为的具体内容、持续时间和严重程度；
- 该事实是否有稳定证据及是否存在重大法律争议；
- 劳动者此前的异议、催告或沟通；
- 解除通知中载明的真实理由、发送时间、对象和送达结果；
- 解除后是否仍有到岗、撤回、协商或其他相互冲突的行为。

**行动原则**

- 被迫解除属于不可逆高风险动作，不把它作为一般降薪、一次迟发工资或沟通不畅的默认选项；
- 解除理由应以发送时已存在且劳动者真实主张的事实为基础；
- 不预设诉讼中可以随意增加或更换解除理由；
- 基础违法事实证据不足时，先补证、催告、确认或转律师评估。
- 这里的证据门槛是判断劳动者是否具有合理、可说明的主张基础，不是要求本Skill代替司法机关作出终局认定；达到门槛后，正式通知必须明确陈述劳动者认定的企业违法事实及《劳动合同法》第三十八条依据。
- 企业可能提出的补正、时效、主体、严重程度或因果关系抗辩，应在通知正文之外单列供劳动者评估和补强，不得据此把劳动者的解除通知降格为中性询问。

**是否发文**

只有主体、事实、理由、真实解除意思和送达方案均确认后，才能把被迫解除通知标为可发送版本。可发送版本应明确企业违法事实、第三十八条具体项、劳动者依法解除决定、经济补偿及相关权利保留。条件未完全闭环时，可生成事实确认、催告，或者提供带醒目事实占位符、措辞完整但标明“暂不可直接发送”的律师复核稿；不得补造事实。

### 4. 解除状态、理由和日期

**要证明的核心事实**

- 谁先作出什么意思表示；
- 通知的形成、发送、接收和生效时间；
- 单位当时明确写明或表达的解除理由；
- 停权、门禁、工资、交接和离职手续与通知是否一致；
- 是否存在个人辞职、协商一致或单位单方解除的混淆。

**下一次沟通**

- 请明确劳动关系是否已经解除、解除主体、理由、生效日期和下一工作日安排；
- 对方称“双方都同意”时，要求列明协商方案和劳动者已作出的具体承诺；
- 劳动者没有辞职意愿时，应真实表达愿意继续履职并请单位安排工作。

**请求成熟门槛**

未锁定解除主体、理由、日期和送达，不直接选择违法解除、经济补偿或继续履行请求。

### 5. 未休年休假

**要证明的核心事实**

- 连续工作年限和对应年度；
- 每年度应休、已休、请休、折抵和支付情况；
- 单位是否明确将集中放假、春节假期或其他停工期间安排为年休假；
- 考勤、请假系统、工资和书面通知如何对应；
- 解除当年度的折算以及请求期间。

**下一次沟通**

- 请单位按年度列明已安排的年休假具体日期、天数及依据；
- 集中放假时，请确认哪些日期属于法定节假日、休息日、福利假或年休假；
- 对单位认定有异议时及时书面保留意见，不只依赖个人回忆。

**举证提示**

单位掌握考勤和休假记录不意味着劳动者可以忽略请假记录、日历、工作消息、工资及当时异议。先建立逐年度日历，再判断举证责任和计算。

### 6. 社会保险和失业待遇

**要证明的核心事实**

- 实际用人单位、劳动合同主体、工资支付主体和参保缴费主体；
- 险种、期间、基数和是否存在断缴、少缴或第三方代缴；
- 当地经办、行政处理和司法救济边界；
- 解除原因是否符合相关待遇条件；
- 未获待遇的原因、金额和因果关系。

**下一次沟通**

- 请单位说明为何由其他主体参保以及三方关系；
- 要求提供参保期间、基数和缴费明细，不把APP显示“已缴费”直接等同于依法由用人单位参保；
- 涉及被迫解除时，先核验当地对该类瑕疵的处理口径和行政救济路径。

**停止条件**

当地规则、经办状态或缴费事实未经核验时，不直接承诺经济补偿、补缴情形或失业待遇损失必然获得支持。

### 7. 固定期限与无固定期限劳动合同

**要证明的核心事实**

- 每份合同的签订日、起止日、次数和主体；
- 劳动者是否提出签订固定期限或无固定期限合同；
- 申请、协商、签署、续签和异议的完整过程；
- 后续固定期限合同是否为真实、自愿意思表示；
- 主张责任的具体期间及期限问题。

**下一次沟通**

- 请单位确认历次合同期限、续签依据和劳动者申请；
- 存在空白签字、后补日期或内容争议时，保存原件、形成过程、经办人、发送记录和同时期材料；
- 不因“连续签了两次”就跳过劳动者意思表示和后续合同履行事实。

## 四、补证方式排序

在合法且与本人争议直接相关的范围内，依次考虑：

1. 保存现有原件和电子原始载体；
2. 导出完整上下文和附件，记录来源与取得时间；
3. 通过正常履职、业务核对或争议沟通取得对方回复；
4. 发送事实确认、核算确认、履职确认或异议文书并保存送达；
5. 通过法定程序申请单位提交、调查取证或证人作证；
6. 证据仍不足且动作不可逆时，停止自动生成并转律师复核。

不得通过越权访问、破解账号、冒充他人、秘密带走无关资料或诱导虚假陈述补证。

## 五、每次诊断的最小输出

针对用户当前最重要的一至三项请求，至少输出：

1. 请求依赖链及当前断点；
2. 关键事实和证据状态；
3. 现有证据质量及对方可能质疑；
4. 今天必须保存的材料；
5. 下一次沟通的具体问题及取证目的；
6. 是否发文、发什么文书、何时发送及如何留痕；
7. 请求目前属于未成熟、可进一步核算、可谈判、可准备仲裁或需律师复核；
8. 地区、时效、主体或法律版本仍需核验的事项。
